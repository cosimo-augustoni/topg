Question hints

A text question can carry up to ten hints. They are all text or all images, and the host reveals them in any order to narrow down the answer. This page is the reference for the GitHub issue: game layouts, host controls, creator editing and data model. The mockups are interactive and use the real proportions of a 1920 × 1080 player screen.

Game screen

Player and spectator pages share the question panel. Use the host panel on the right to show or hide hints, the same way the host does during a game. Hidden hints keep their slot and show their number, so revealing one never moves the others.

Layout rules

The layout depends on the total number of hints, not on how many are shown. It is fixed from the moment the question opens.

No hints

Nothing changes. The question text is the large centered heading, as today.

Text hints

  • 1–3: stacked vertically, full width, top-aligned. Every row is one third of the area, so rows keep the same height and spacing whatever the count.
  • 4–5: one row, centered horizontally and vertically.
  • 6–10: two rows; the top row gets ceil(n / 2).

Image hints

  • 1–5: one row, centered horizontally and vertically.
  • 6–10: two rows; the top row gets ceil(n / 2).
  • Tiles are 4:3 and images are fitted with object-fit: contain. If any hint has a caption, every tile gets a 40 px caption strip so the tiles stay the same height.

Shared

  • All tiles are the same size. The column count of the longer row sets the width, and the shorter row is centered.
  • A hidden tile shows its number, which helps the host match it to the host table. A shown tile shows only its content, without a number.
  • The question text becomes a one-line header (about 46 px). While it is hidden, the hints are hidden too, placeholders included. Each hint keeps its own toggle and appears as set once the question text is shown.
  • Text shrinks to fit its tile. Try “250-character texts” with 10 hints to see the worst case.

Creator inspector

A new “Hints” section in the question inspector, below the correct answer. It is only shown for text questions. Edits here update the game screen above.

Behaviour

  • Empty: “Text hint” and “Image hint” buttons. The first hint you add sets the type, so there's no type selector until one is needed.
  • With hints: a Text / Image toggle in the section header. Switching with hints present asks for confirmation, then replaces them with one empty hint of the new type.
  • Order: move buttons on each hint; numbers always follow the list. The order here is the order in the game.
  • Limit: the counter shows n / 10; “Add hint” is disabled at 10.
  • Text: multi-line field, capped at 250 characters, with a live counter.
  • Image: the existing ImageDropZone plus an optional caption. Hint images are content-addressed like the others, so the export ZIP and the project file pick them up through Images().
  • Validation (errors, block export): “Hint 2 has no text.” and “Hint 1 has no image.” An empty caption is fine.
  • Question type change from Text to Image with hints present uses the existing confirmation and says the hints will be removed.
  • Duplicate copies the hints.

Data model

The hint type is stored once, on the question, so a mixed question can't be stored at all. Hints cascade with their question, which keeps the “replace existing” delete in import.sql working unchanged.

Touch points

  • Shared/HintType.cs: new enum used by both creator and game.
  • Templating: QuestionHint record, TextQuestion.Hints, migration, TemplateService include.
  • Quiz/Execution: runtime hints with IsVisible. A [Flags] enum can't hold ten independent toggles.
  • SqlExport: questions with hints get a single-row insert RETURNING "Id" INTO question_id, then the hint insert. The batched insert stays for the rest, and DollarQuoteTag scans hint text too.
  • Golden files, SqlImportTests, validator, editing and project-file round-trip tests.
